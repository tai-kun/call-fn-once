This page uses `callFnOnce` to explain the minimal usage. The other two functions take arguments the same way.

## Basic usage [#basic-usage]

<Steps>
  <Step title="Prepare a CacheMap">
    Create a `Map` that holds results. Results are cached independently per key.

    ```ts cache.ts
    import { callFnOnce } from "call-fn-once";

    const cacheMap: callFnOnce.CacheMap = new Map();
    ```
  </Step>
  <Step title="Pass a key and a function">
    When called with the same key, later calls return the cached result without running the function.

    ```ts
    import { callFnOnce } from "call-fn-once";

    const cacheMap: callFnOnce.CacheMap = new Map();
    let callCount = 0;

    const first = callFnOnce(cacheMap, "config", () => {
      callCount += 1;

      return { timeout: 3000 };
    });

    const second = callFnOnce(cacheMap, "config", () => {
      callCount += 1;

      return { timeout: 9999 };
    });

    console.log(first);
    console.log(first === second);
    console.log(callCount);
    ```

    `first` and `second` are the same reference, and `callCount` stays `1`.
  </Step>
  <Step title="Separate by key">
    Different keys each run once.

    ```ts
    import { callFnOnce } from "call-fn-once";

    const cacheMap: callFnOnce.CacheMap = new Map();

    const a = callFnOnce(cacheMap, "a", () => "A");
    const b = callFnOnce(cacheMap, "b", () => "B");
    const cachedA = callFnOnce(cacheMap, "a", () => "A2");

    console.log(a);
    console.log(b);
    console.log(cachedA);
    ```
  </Step>
</Steps>

## Options form [#options-form]

When there are many arguments, or you want to keep the key and function together, you can pass an object instead. This form shares the cache with the positional form.

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

const first = callFnOnce({
  cacheMap,
  key: "config",
  fn: () => ({ timeout: 3000 }),
});

const second = callFnOnce(cacheMap, "config", () => ({ timeout: 9999 }));

console.log(first === second);
```

:::tip
Both forms behave identically. Pick whichever reads better at each call site.
:::

## Common gotchas [#notes]

- `undefined` is cached correctly because existence is checked with `has()`.
- A sync exception is not cached. The next call runs the function again.
- Caches are independent per `CacheMap`. Use a separate `Map` when the use cases differ.
