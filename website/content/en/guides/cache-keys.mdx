## Choosing keys [#choosing-keys]

Keys are typed as `unknown`, so values other than strings work too. The unit of cache sharing is exactly the key.

| Key type | Good for | Example |
| --- | --- | --- |
| String | Named, single computations | `"config"`, `"user"` |
| Object | Splitting by argument combinations | `{ userId: 1 }` |
| Object reference | Splitting per instance | `request` |

```ts keys.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

// String key: share a single config value.
callFnOnce(cacheMap, "config", () => ({ timeout: 3000 }));

// Reference key: keep values independent per request.
declare const request: object;
callFnOnce(cacheMap, request, () => "per-request value");
```

:::warning
A fresh object literal on every call is never shared because the reference differs. To share by value, build a stable key such as a string.
:::

```ts bad-key.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

// Never shared because the reference differs each time.
callFnOnce(cacheMap, { userId: 1 }, () => "first");
callFnOnce(cacheMap, { userId: 1 }, () => "second");
```

To share by value, use a stringified key.

```ts good-key.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

function getUser(userId: number): string {
  return callFnOnce(cacheMap, `user:${userId}`, () => `user-${userId}`);
}
```

## Separating CacheMaps [#sharing-cache-maps]

Caches are independent per `CacheMap`. Use a separate `Map` when the purpose or lifetime differs.

```ts maps.ts
import { callFnOnce } from "call-fn-once";

const configMap: callFnOnce.CacheMap = new Map();
const requestMap: callFnOnce.CacheMap = new Map();

// A config value shared across the whole app.
callFnOnce(configMap, "config", () => ({ timeout: 3000 }));

// A disposable per-request value.
declare const request: object;
callFnOnce(requestMap, request, () => "per-request value");
```

Sharing a `Map` at module scope reuses it across the app. In tests or per-request code, create a fresh `Map` to avoid interfering with other runs.

### Never share across functions [#no-sharing-across-functions]

Never reuse the same `CacheMap` across `callFnOnce`, `callAsyncableFnOnce`, and `callAbortableFnOnce`. Create a fresh `Map` per function. It may appear to work while keys never collide, but a future key collision breaks reads, so splitting by key is not a workaround.

Each function stores records in a different internal shape. In particular, `callAbortableFnOnce` stores `{ busy, value }` wrappers, so sharing a `Map` with another function silently returns a corrupted value that is neither the cached value nor a fresh one. The types cannot catch this because everything is passable via `Map<unknown, any>`.

:::danger[Sharing across functions is forbidden]
Never pass the same `Map` to more than one function. Use a separate `Map` per function.
:::

```ts bad-share.ts
import { callAbortableFnOnce, callFnOnce } from "call-fn-once";

// Never reuse the same Map.
const cacheMap = new Map();

callFnOnce(cacheMap, "key", () => "hello");
// Returns undefined, which is neither "hello" nor "world".
callAbortableFnOnce(cacheMap, "key", () => "world");
```

```ts good-share.ts
import { callAbortableFnOnce, callFnOnce } from "call-fn-once";

// Use a separate Map per function.
const syncMap: callFnOnce.CacheMap = new Map();
const abortableMap: callAbortableFnOnce.CacheMap = new Map();

callFnOnce(syncMap, "key", () => "hello");
callAbortableFnOnce(abortableMap, "key", () => "world");
```

## Memory [#memory]

- Drop caches you no longer need with `cacheMap.delete(key)`.
- Discarding the `Map` itself discards the corresponding caches.
- The internal state of `callAbortableFnOnce` is held in a `WeakMap`, so dropping the `CacheMap` drops it too.

:::note
In long-running apps, ever-growing keys increase memory usage. For short-lived use cases, use a separate `Map` and discard it when done.
:::
