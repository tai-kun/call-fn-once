title: callAsyncableFnOnce
description: The specification of the function that accepts both synchronous and asynchronous values and shares an in-flight Promise.
---

Runs the callback once per specified key and caches the result. It accepts both synchronous and asynchronous values. For asynchronous values it shares the in-flight `Promise`, and after resolution it returns the settled value.

## Usage [#usage]

Synchronous values are handled the same as with `callFnOnce`. Returning an asynchronous value shares the same `Promise` until it resolves.

```ts
import { callAsyncableFnOnce } from "call-fn-once";

const cacheMap: callAsyncableFnOnce.CacheMap = new Map();

const pending = callAsyncableFnOnce(cacheMap, "user", async () => {
  const res = await fetch("https://example.com/user");
  return res.json();
});
```

The options form yields the same result.

```ts options.ts
import { callAsyncableFnOnce } from "call-fn-once";

const cacheMap: callAsyncableFnOnce.CacheMap = new Map();

const pending = callAsyncableFnOnce({
  cacheMap,
  key: "user",
  fn: async () => "ok",
});
```

## Behavior [#behavior]

### Synchronous values [#sync-values]

- It caches the execution result of a synchronous value as-is.
- It caches `undefined` correctly too.
- It does not cache a synchronous exception. The next call runs it again.

### Asynchronous values [#async-values]

- Concurrent calls before resolution are combined into a single execution, and the callback runs only once.
- After resolution, the cache is replaced with the settled value, and the next call returns the value directly rather than a `Promise`.
- On rejection, the cache is discarded, so the next call can run again. A rejection is passed to all waiting calls.
- Thenables other than `Promise` are also treated as asynchronous.
- The same key of the same `Map` cannot be called again during the callback's synchronous execution. Reentry synchronously throws `ReentrantCallError`. A call that joins later to share an in-flight `Promise` is not subject to this.
- If the same `CacheMap` is used by another function, it synchronously throws `MismatchedCacheMapError` regardless of the key. Split the `Map` per function.

```ts
import { callAsyncableFnOnce } from "call-fn-once";

const cacheMap: callAsyncableFnOnce.CacheMap = new Map();
let callCount = 0;

const first = Promise.resolve(
  callAsyncableFnOnce(cacheMap, "key", () => {
    callCount += 1;
    return Promise.resolve("ok");
  }),
);

const second = Promise.resolve(
  callAsyncableFnOnce(cacheMap, "key", () => {
    callCount += 1;
    return Promise.resolve("unexpected");
  }),
);

await first;
await second;
console.log(callCount); // 1

const cached = callAsyncableFnOnce(cacheMap, "key", () => {
  throw new Error("it does not run again after resolution");
});

console.log(cached); // "ok"
```

:::note
Even when the resolved value is `undefined`, it is cached as the settled value.
:::

`callAsyncableFnOnce.CacheMap` requires `has()`, `get()`, `set()`, and `delete()`. You can pass a `Map` or a `WeakMap` directly. Only objects can be used as `WeakMap` keys.

The return type is `callAsyncableFnOnce.Return<V>`. When `V` is a Thenable, it becomes the resolved value wrapped in `MaybePromise`; otherwise it stays as `V`.

```ts types.ts
import { callAsyncableFnOnce } from "call-fn-once";

const syncCacheMap: callAsyncableFnOnce.CacheMap<string, number> = new Map();
const asyncCacheMap: callAsyncableFnOnce.CacheMap<string, Promise<number>> = new Map();

const syncValue: number = callAsyncableFnOnce(syncCacheMap, "sync", () => 1);
const asyncValue: number | Promise<number> = callAsyncableFnOnce(asyncCacheMap, "async", () =>
  Promise.resolve(1),
);
```

The return type is determined by the `CacheMap` type argument `V`, not by the callback's return value. For how to specify `K` and `V` to prevent compile-time mistakes, see [Improve safety with type arguments](/how-to/type-safely).
