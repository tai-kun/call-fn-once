---
title: callFnOnce
description: The spec of the function that runs a sync function once per key and shares the result.
---

Runs the callback once per key and caches the result. Later calls with the same key return the cached result without running it again.

## Usage [#usage]

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

const result = callFnOnce(cacheMap, "key", () => 42);
```

The options form returns the same result.

```ts options.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

const result = callFnOnce({
  cacheMap,
  key: "key",
  fn: () => 42,
});
```

## Behavior [#behavior]

- `undefined` results are cached too, because existence is checked with `has()`.
- Cached objects are returned by the same reference.
- A sync exception is not cached. The next call runs the function again.
- Caches are independent per key.
- Caches are independent per `CacheMap`. Use a separate `Map` when the use cases differ.
- Using the same `CacheMap` from another function throws `MismatchedCacheMapError` synchronously, regardless of the key. Use a separate `Map` per function.

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();
let callCount = 0;

callFnOnce(cacheMap, "key", () => {
  callCount += 1;

  return undefined;
});

const cached = callFnOnce(cacheMap, "key", () => {
  callCount += 1;

  return "second";
});

console.log(cached);
console.log(callCount);
```

:::warning
Passing an async function caches the `Promise` object itself. It does not share the pending state or retry on rejection. Use `callAsyncableFnOnce` for async work.
:::

`callFnOnce.CacheMap` only requires `has()`, `get()`, and `set()`. Both `Map` and `WeakMap` can be passed directly; `delete()` is not required, and `WeakMap` keys must be objects.

The return type is `callFnOnce.Return<V>`, which is the same as `V`.

```ts types.ts
import { callFnOnce } from "call-fn-once";

const numberCacheMap: callFnOnce.CacheMap<string, number> = new Map();
const undefinedCacheMap: callFnOnce.CacheMap<string, undefined> = new Map();

const num: number = callFnOnce(numberCacheMap, "num", () => 1);
const nothing: undefined = callFnOnce(undefinedCacheMap, "nothing", () => undefined);
```

### Type inference [#type-inference]

The return type comes from the `V` type argument of `CacheMap`, not from the callback's return value. The `key` type also comes from the `K` type argument of `CacheMap`.

Inferring the return type from the callback would let callers use a different type for the same key on each call, so the following code would type-check. The second call is typed as `string`, but at runtime it returns the `number` `42` cached by the first call.

```ts unsafe.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

const value1: number = callFnOnce(cacheMap, "key", () => 42);
console.log(value1); // 42

const value2: string = callFnOnce(cacheMap, "key", () => "42");
console.log(value2); // 42
```

To get the constraint, specify the key and value types with the `CacheMap` type arguments. With `CacheMap<string, number>`, returning a `string` for the same key is a compile error.

```ts typed.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap<string, number> = new Map();

const value1: number = callFnOnce(cacheMap, "key", () => 42);

// Type error: the same key can only be associated with a number.
const value2: string = callFnOnce(cacheMap, "key", () => "42");
```

If you write `CacheMap` without its type arguments, `V` is `any`, so specify them when you need the constraint.
