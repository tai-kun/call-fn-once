---
title: callFnOnce
description: The specification of the function that runs a synchronous callback once per key and shares the result.
---

Runs the callback once per specified key and caches the result. The second and later calls return the cached result without re-running.

## Usage [#usage]

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

const result = callFnOnce(cacheMap, "key", () => 42);
```

The options form yields the same result.

```ts options.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

const result = callFnOnce({
  cacheMap,
  key: "key",
  fn: () => 42,
});
```

## Behavior [#behavior]

- It caches an `undefined` result too. This is because existence is checked with `has()`.
- It returns a cached object by the same reference.
- It does not cache a thrown synchronous exception. The next call runs it again.
- It caches independently per key.
- It is independent per `CacheMap`. If use cases differ, split the `Map`.
- The same key of the same `Map` cannot be called again during the callback's synchronous execution. Reentry synchronously throws `ReentrantCallError`. Split the keys to avoid it.
- If the same `CacheMap` is used by another function, it synchronously throws `MismatchedCacheMapError` regardless of the key. Split the `Map` per function.

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();
let callCount = 0;

callFnOnce(cacheMap, "key", () => {
  callCount += 1;

  return undefined;
});

const cached = callFnOnce(cacheMap, "key", () => {
  callCount += 1;

  return "second";
});

console.log(cached); // undefined
console.log(callCount); // 1
```

:::warning
Passing an async function caches the `Promise` object itself. There is no sharing of pending resolution or re-execution on rejection. If asynchronous work is involved, use `callAsyncableFnOnce`.
:::

`callFnOnce.CacheMap` requires only `has()`, `get()`, and `set()`. You can pass a `Map` or a `WeakMap` directly. It does not require `delete()`. Only objects can be used as `WeakMap` keys.

The return type is `callFnOnce.Return<V>`, which is the same as `V`.

```ts types.ts
import { callFnOnce } from "call-fn-once";

const numberCacheMap: callFnOnce.CacheMap<string, number> = new Map();
const undefinedCacheMap: callFnOnce.CacheMap<string, undefined> = new Map();

const num: number = callFnOnce(numberCacheMap, "num", () => 1);
const nothing: undefined = callFnOnce(undefinedCacheMap, "nothing", () => undefined);
```

The return type is determined by the `CacheMap` type argument `V`, not by the callback's return value. For how to specify `K` and `V` to prevent compile-time mistakes, see [Improve safety with type arguments](/how-to/type-safely).
