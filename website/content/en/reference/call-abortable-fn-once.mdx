title: callAbortableFnOnce
description: The specification of the function that supports sync and async and performs cooperative aborting via AbortSignal.
---

Runs the callback once per specified key and caches the result. It accepts both synchronous and asynchronous values. For asynchronous values it shares the in-flight `Promise`, and after resolution it reuses that value. The in-flight callback is aborted only when every caller has aborted.

## Usage [#usage]

The callback receives a signal for aborting internal work. The caller's signal can be passed as the fourth argument or in the options form.

```ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const controller = new AbortController();

const pending = callAbortableFnOnce(
  cacheMap,
  "user",
  async (signal) => {
    const res = await fetch("https://example.com/user", { signal });
    return res.json();
  },
  controller.signal,
);
```

In the options form, pass it via the `signal` field.

```ts options.ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const controller = new AbortController();

const pending = callAbortableFnOnce({
  cacheMap,
  key: "user",
  fn: async (signal) => "ok",
  signal: controller.signal,
});
```

## Behavior [#behavior]

### Synchronous execution [#sync-execution]

- It passes a signal for aborting internal work to the callback. A synchronous success is cached as-is.
- A synchronous exception leaves no state, and the next call runs it again.
- If an already-aborted signal is passed, it throws the abort reason without running the function.

### Asynchronous execution [#async-execution]

- In-flight asynchronous work is shared. After resolution it is cached as the settled value, and the next call returns the value directly.
- Asynchronous failures are not cached. The next call runs it again.
- It caches independently per key.

### Abort [#abort]

The rules for aborting are as follows.

- If even one waiting caller remains, the internal work is not aborted.
- Only when every waiting caller has aborted is the internal work aborted and the cache discarded.
- Because no cache remains after all have aborted, the next call runs it again. A result from an old execution that settles late does not overwrite it.
- As long as there is a call that specifies no signal, the internal work is not aborted. Internally, a dummy signal that never fires is registered as a waiter to prevent the waiter set from becoming empty.
- After settlement, the cache is returned as an ordinary value. However, when called together with an already-aborted signal, it throws the abort reason even if a cache exists.

```ts abort.ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const firstController = new AbortController();
const secondController = new AbortController();

const first = callAbortableFnOnce(
  cacheMap,
  "key",
  (signal) => fetch("https://example.com/data", { signal }),
  firstController.signal,
);

const second = callAbortableFnOnce(
  cacheMap,
  "key",
  (signal) => fetch("https://example.com/data", { signal }),
  secondController.signal,
);

// Even if only the first aborts, the internal fetch continues.
firstController.abort();

// When the second also aborts, no waiters remain, so the internal work is aborted.
secondController.abort();
```

:::note
The abort reason carries the value of `AbortSignal.reason` as-is. If you call `controller.abort()` without specifying a reason, it becomes a `DOMException` of type `AbortError`.
:::

`callAbortableFnOnce.CacheMap` requires `has()`, `get()`, `set()`, and `delete()`. You can pass a `Map` or a `WeakMap` directly. Only objects can be used as `WeakMap` keys.

The return type is `callAbortableFnOnce.Return<V>`. When `V` is a Thenable, it becomes the resolved value wrapped in `MaybePromise`; otherwise it stays as `V`.

The value stored in the `CacheMap` is managed by the `callAbortableFnOnce.Cache` type. While running, it stores `busy: true` and a `Promise`; when complete, it stores `busy: false` and the settled value.

The return type is determined by the `CacheMap` type argument `V`, not by the callback's return value. For how to specify `K` and `V` to prevent compile-time mistakes, see [Improve safety with type arguments](/how-to/type-safely).

### Error classes [#error-classes]

- If an in-flight record (`busy: true`) exists but there is no waiter information, it synchronously throws `InconsistentCacheError` as a cache inconsistency, without running the function again.
- The same key of the same `Map` cannot be called again during the callback's synchronous execution. A reentrant call synchronously throws `ReentrantCallError`. A call that joins later to share an in-flight `Promise` is not subject to this.
- If the same `CacheMap` is used by another function, it synchronously throws `MismatchedCacheMapError` regardless of the key.

All can be identified with `instanceof`. For details and identification examples, see [Error classes](/reference/errors).
