title: 失敗を再試行する

## 失敗した結果はキャッシュされない [#policy]

3 つの関数は成功した結果だけをキャッシュします。同期例外や非同期拒否が起きた場合は状態を残さないため、同じキーでもう一度呼び出すと再実行されます。呼び出し元にはコールバック関数の例外や拒否理由がそのまま伝わります。

## 同期例外を再試行する [#sync]

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();
let attempts = 0;

function load() {
  return callFnOnce(cacheMap, "config", () => {
    attempts += 1;

    if (attempts === 1) {
      throw new Error("一時的なエラー");
    }

    return { timeout: 3000 };
  });
}

try {
  load(); // 1 回目はエラーになります
} catch (error) {
  console.log(error); // Error: 一時的なエラー
}

const config = load(); // 再実行され、成功した結果がキャッシュされます

console.log(config); // { timeout: 3000 }
```

## 非同期拒否を再試行する [#async]

```ts
import { callAsyncableFnOnce } from "call-fn-once";

const cacheMap: callAsyncableFnOnce.CacheMap = new Map();
let attempts = 0;

async function load() {
  return callAsyncableFnOnce(cacheMap, "user", async () => {
    attempts += 1;

    if (attempts === 1) {
      throw new Error("一時的なエラー");
    }

    return "tai-kun";
  });
}

await load().catch((error: unknown) => error); // 1 回目は拒否されます

const user = await load(); // 再実行され、成功した結果がキャッシュされます

console.log(user); // "tai-kun"
```

解決待ちの間に複数の呼び出し元が待機していた場合、拒否はすべての呼び出し元に伝わり、キャッシュからエントリーが削除されます。次の呼び出しは新しい実行になります。

## リトライ処理を組み込む [#retry]

`call-fn-once` は再試行の回数や間隔を管理しません。失敗がキャッシュされないことを利用して、呼び出し側で再試行を制御できます。

```ts
async function withRetry<T>(
  fn: () => Promise<T>,
  attempts: number,
): Promise<T> {
  for (let attempt = 1; ; attempt += 1) {
    try {
      return await fn();
    } catch (error) {
      if (attempt >= attempts) {
        throw error;
      }
    }
  }
}

const user = await withRetry(() => load(), 3);
```

間隔を空けて再試行したい場合は、呼び出しの前に待機を入れてください。

## 誤用を示すエラーの対処 [#guard-errors]

ライブラリー自身の誤用は専用のエラークラスとして同期的に投げられます。原因に応じて次のように対処してください。

| エラークラス | 原因 | 対処 |
| --- | --- | --- |
| `ReentrantCallError` | 同じキーで同期的に再入した | キーを分ける |
| `MismatchedCacheMapError` | 別の関数で使われた `CacheMap` を渡した | 関数ごとに `Map` を分ける |
| `InconsistentCacheError` | 実行中の記録と内部状態が一致しない | `CacheMap` を直接編集しない |

`ReentrantCallError` は同じキーの実行中に同じキーで再び呼び出したときに発生します。再帰的な計算を共有したい場合は、階層ごとに異なるキーを割り当ててください。

`MismatchedCacheMapError` の対処は [CacheMap のスコープを設計する](/how-to/manage-cache-maps)を、エラークラスの一覧は[エラークラス](/reference/errors)を参照してください。
