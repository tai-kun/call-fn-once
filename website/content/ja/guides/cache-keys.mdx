## キーの選び方 [#choosing-keys]

キーは `unknown` 型のため、文字列以外の値も使えます。キャッシュの共有単位がそのままキーになります。

| キーの種類       | 適した場面                                 | 例                   |
| ---------------- | ------------------------------------------ | -------------------- |
| 文字列           | 名前付きの単一処理に使います               | `"config"`、`"user"` |
| オブジェクト     | 引数の組み合わせごとに分ける場合に使います | `{ userId: 1 }`      |
| オブジェクト参照 | インスタンスごとに分ける場合に使います     | `request`            |

```ts keys.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

// 文字列キー: 単一の設定値を共有します。
callFnOnce(cacheMap, "config", () => ({ timeout: 3000 }));

// 参照キー: リクエストごとに独立させます。
declare const request: object;
callFnOnce(cacheMap, request, () => "per-request value");
```

:::warning
毎回新しいオブジェクトをキーにすると、参照が異なるため共有されません。値で共有したい場合は、文字列などの安定したキーを組み立ててください。
:::

```ts bad-key.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

// 毎回参照が異なるため、共有されません。
callFnOnce(cacheMap, { userId: 1 }, () => "first");
callFnOnce(cacheMap, { userId: 1 }, () => "second");
```

値で共有したい場合は、内容を文字列化したキーを使ってください。

```ts good-key.ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

function getUser(userId: number): string {
  return callFnOnce(cacheMap, `user:${userId}`, () => `user-${userId}`);
}
```

## CacheMap の使い分け [#sharing-cache-maps]

`CacheMap` ごとにキャッシュは独立します。用途や寿命が異なる場合は `Map` を分けてください。

```ts maps.ts
import { callFnOnce } from "call-fn-once";

const configMap: callFnOnce.CacheMap = new Map();
const requestMap: callFnOnce.CacheMap = new Map();

// アプリ全体で共有する設定値です。
callFnOnce(configMap, "config", () => ({ timeout: 3000 }));

// リクエスト単位で使い捨てる値です。
declare const request: object;
callFnOnce(requestMap, request, () => "per-request value");
```

モジュール直下で `Map` を共有すると、アプリ全体で再利用できます。テストやリクエスト単位では、新しい `Map` を作成すればほかの実行と干渉しません。

### 関数間での共有禁止 [#no-sharing-across-functions]

`callFnOnce`、`callAsyncableFnOnce`、`callAbortableFnOnce` で同じ `CacheMap` を使い回さないでください。関数ごとに新しい `Map` を作成してください。キーが重ならなければ壊れませんが、将来のキーの衝突で壊れるため、キー分けでの回避もできません。

内部の記録形式が関数ごとに異なります。特に `callAbortableFnOnce` は `{ busy, value }` 形式のラッパーを格納するため、ほかの関数と `Map` を共有すると、キャッシュ値でも新規実行値でもない壊れた値が黙って返ります。型上は `Map<unknown, any>` 経由で渡せてしまうため、コンパイル時にも検出できません。

:::danger[関数間での共有は禁止]
同じ `Map` を複数の関数に渡さないでください。関数ごとに `Map` を分けてください。
:::

```ts bad-share.ts
import { callAbortableFnOnce, callFnOnce } from "call-fn-once";

// 同じ Map を使い回してはいけません。
const cacheMap = new Map();

callFnOnce(cacheMap, "key", () => "hello");
// "hello" でも "world" でもない undefined が返ります。
callAbortableFnOnce(cacheMap, "key", () => "world");
```

```ts good-share.ts
import { callAbortableFnOnce, callFnOnce } from "call-fn-once";

// 関数ごとに Map を分けます。
const syncMap: callFnOnce.CacheMap = new Map();
const abortableMap: callAbortableFnOnce.CacheMap = new Map();

callFnOnce(syncMap, "key", () => "hello");
callAbortableFnOnce(abortableMap, "key", () => "world");
```

## メモリー管理 [#memory]

- 不要になったキャッシュは `cacheMap.delete(key)` で破棄できます。
- `Map` 自体を破棄すると、対応するキャッシュも破棄されます。
- `callAbortableFnOnce` の内部状態は `WeakMap` で管理されるため、`CacheMap` を破棄すれば一緒に破棄されます。
- `callAbortableFnOnce` の `CacheMap` に `busy: true` の記録を直接書き込むと不整合な状態になり、次回呼び出しでは関数を再実行せず `InconsistentCacheError`（`code: ERR_CALL_FN_ONCE_INCONSISTENT_CACHE`）を同期的に投げる場合があります。破棄目的の `cacheMap.delete(key)` は対象外です。

:::note
長期稼働するアプリでは、キーが増え続けるとメモリー使用量も増えます。寿命の短い用途では `Map` を分けて、使い終わったら破棄してください。
:::
