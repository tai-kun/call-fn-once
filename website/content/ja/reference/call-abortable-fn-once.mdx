title: callAbortableFnOnce
description: 同期と非同期に対応し、AbortSignal による協調的な中断を行うための関数の仕様です。
---

指定されたキーごとに、コールバック関数を一度だけ実行して結果をキャッシュします。同期値と非同期値のどちらも受け付けます。非同期の場合は解決待ちの `Promise` を共有し、解決後はその値を再利用します。実行中のコールバック関数を中断するのは、すべての呼び出し元が中断したときに限ります。

## 使い方 [#usage]

コールバック関数は内部処理の中断用シグナルを受け取ります。呼び出し元のシグナルは第 4 引数またはオプション形式で渡せます。

```ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const controller = new AbortController();

const pending = callAbortableFnOnce(
  cacheMap,
  "user",
  async (signal) => {
    const res = await fetch("https://example.com/user", { signal });
    return res.json();
  },
  controller.signal,
);
```

オプション形式では `signal` フィールドで渡します。

```ts options.ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const controller = new AbortController();

const pending = callAbortableFnOnce({
  cacheMap,
  key: "user",
  fn: async (signal) => "ok",
  signal: controller.signal,
});
```

## 仕様 [#behavior]

### 同期実行 [#sync-execution]

- コールバック関数に内部処理の中断用シグナルを渡します。同期成功はそのままキャッシュします。
- 同期例外は状態を残さず、次回呼び出しで再実行します。
- 中断済みのシグナルを渡した場合は、関数を実行せずに中断理由を投げます。

### 非同期実行 [#async-execution]

- 解決待ちの非同期処理は共有します。解決後は確定値としてキャッシュし、次回呼び出しでは値を直接返します。
- 非同期失敗はキャッシュしません。次回呼び出しで再実行します。
- キーごとに独立してキャッシュします。

### 中断 [#abort]

中断の規則は次のとおりです。

- 待機中の呼び出し元が 1 つでも残っていれば、内部処理は中断しません。
- 待機中の呼び出し元がすべて中断したときに限り、内部処理を中断してキャッシュを破棄します。
- すべて中断した後はキャッシュが残らないため、次回呼び出しで再実行できます。遅れて確定した古い結果では上書きしません。
- シグナルを指定しない呼び出しがある限り、内部処理は中断しません。内部では発火しないダミーのシグナルを待機者として登録し、待機者が空になるのを防ぎます。
- 確定後のキャッシュは通常の値として返します。ただし、中断済みシグナルと一緒に呼び出した場合は、キャッシュがあっても中断理由を投げます。

```ts abort.ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const firstController = new AbortController();
const secondController = new AbortController();

const first = callAbortableFnOnce(
  cacheMap,
  "key",
  (signal) => fetch("https://example.com/data", { signal }),
  firstController.signal,
);

const second = callAbortableFnOnce(
  cacheMap,
  "key",
  (signal) => fetch("https://example.com/data", { signal }),
  secondController.signal,
);

// 1 つ目だけ中断しても、内部の fetch は継続します。
firstController.abort();

// 2 つ目も中断すると、待機者がいなくなるため内部処理が中断します。
secondController.abort();
```

:::note
中断理由は `AbortSignal.reason` の値がそのまま伝わります。理由を指定せずに `controller.abort()` を呼んだ場合は、`AbortError` の `DOMException` になります。
:::

`callAbortableFnOnce.CacheMap` が求めるのは `has()`・`get()`・`set()`・`delete()` です。`Map` と `WeakMap` をそのまま渡せます。`WeakMap` のキーにはオブジェクトだけを指定できます。

戻り値の型は `callAbortableFnOnce.Return<V>` です。`V` が Thenable の場合は解決値を `MaybePromise` でラップした型になり、それ以外の場合は `V` のままです。

`CacheMap` に格納する値は `callAbortableFnOnce.Cache` 型で管理します。実行中は `busy: true` と `Promise`、完了後は `busy: false` と確定値を格納します。

戻り値の型はコールバック関数の戻り値ではなく `CacheMap` の型引数 `V` から決まります。`K` と `V` を指定してコンパイル時の誤りを防ぐ方法は、[型引数で安全性を高める](/how-to/type-safely)を参照してください。

### エラークラス [#error-classes]

- 実行中の記録 (`busy: true`) があるにもかかわらず待機情報がない場合、キャッシュの不整合として、関数を再実行せず `InconsistentCacheError` を同期的に投げます。
- 同一 `Map` の同一キーはコールバック関数の同期的な実行中に再び呼び出せません。再入した呼び出しは `ReentrantCallError` を同期的に投げます。解決待ちの `Promise` を後から共有する呼び出しは対象外です。
- 別の関数で同じ `CacheMap` を使うと、キーによらず `MismatchedCacheMapError` を同期的に投げます。

いずれも `instanceof` で判定できます。詳細と判定の例は[エラークラス](/reference/errors)を参照してください。
