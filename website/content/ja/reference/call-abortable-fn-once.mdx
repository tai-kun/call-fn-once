title: callAbortableFnOnce
description: 同期と非同期に対応し、AbortSignal による協調的な中断を行うための関数の仕様です。
---

指定されたキーごとに、コールバック関数を一度だけ実行して結果をキャッシュします。同期値と非同期値のどちらも受け付けます。非同期の場合は解決待ちの `Promise` を共有し、解決後はその値を再利用します。実行中のコールバック関数を中断するのは、すべての呼び出し元が中断したときに限ります。

## 使い方 [#usage]

コールバック関数は内部処理の中断用シグナルを受け取ります。呼び出し元のシグナルは、第 4 引数またはオプション形式で渡せます。

```ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const controller = new AbortController();

const pending = callAbortableFnOnce(
  cacheMap,
  "user",
  async (signal) => {
    const res = await fetch("https://example.com/user", { signal });
    return res.json();
  },
  controller.signal,
);
```

オプション形式では `signal` フィールドで渡します。

```ts options.ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const controller = new AbortController();

const pending = callAbortableFnOnce({
  cacheMap,
  key: "user",
  fn: async (signal) => "ok",
  signal: controller.signal,
});
```

## 仕様 [#behavior]

### 同期実行 [#sync-execution]

- コールバック関数に内部処理の中断用シグナルを渡します。同期成功はそのままキャッシュします。
- 同期例外は状態を残さず、次回呼び出しで再実行します。
- 中断済みのシグナルを渡した場合は、関数を実行せずに中断理由を投げます。

### 非同期実行 [#async-execution]

- 解決待ちの非同期処理は共有します。解決後は確定値としてキャッシュし、次回呼び出しでは値を直接返します。
- 非同期失敗はキャッシュしません。次回呼び出しで再実行します。
- キーごとに独立してキャッシュします。

### 中断 [#abort]

中断の規則は次のとおりです。

- 待機中の呼び出し元が 1 つでも残っていれば、内部処理は中断しません。
- 待機中の呼び出し元がすべて中断したときに限り、内部処理を中断してキャッシュを破棄します。
- すべて中断した後はキャッシュが残らないため、次回呼び出しで再実行できます。遅れて確定した古い結果では上書きしません。
- シグナルを指定しない呼び出しがある限り、内部処理は中断しません。内部では発火しないダミーのシグナルを待機者として登録し、待機者が空になるのを防ぎます。
- 確定後のキャッシュは通常の値として返します。ただし、中断済みシグナルと一緒に呼び出した場合は、キャッシュがあっても中断理由を投げます。

```ts abort.ts
import { callAbortableFnOnce } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();
const firstController = new AbortController();
const secondController = new AbortController();

const first = callAbortableFnOnce(
  cacheMap,
  "key",
  (signal) => fetch("https://example.com/data", { signal }),
  firstController.signal,
);

const second = callAbortableFnOnce(
  cacheMap,
  "key",
  (signal) => fetch("https://example.com/data", { signal }),
  secondController.signal,
);

// 1 つ目だけ中断しても、内部の fetch は継続します。
firstController.abort();

// 2 つ目も中断すると、待機者がいなくなるため内部処理が中断します。
secondController.abort();
```

:::tip
中断理由は `abort-signal-utils` の `getAbortReason` で取得し、`throwIfAborted` で事前に確認します。中断理由はそのまま伝わるため、呼び出し元ごとの理由が混ざることはありません。
:::

戻り値の型は `callAbortableFnOnce.Return<T>` です。`T` が Thenable の場合は解決値を `MaybePromise` でラップした型になり、それ以外の場合は `T` のままです。

キャッシュの値は `callAbortableFnOnce.Cache` として保持します。実行中は `busy: true` と `Promise`、完了後は `busy: false` と確定値を格納します。

実行中の記録（`busy: true`）があるにもかかわらず待機情報がない場合、キャッシュの不整合として関数を再実行せず `InconsistentCacheError` を同期的に投げます。`code` は `ERR_CALL_FN_ONCE_INCONSISTENT_CACHE` です。

同一 `Map` の同一キーは、コールバック関数の同期的な実行中に再び呼び出せません。再入した呼び出しは `ReentrantCallError`（`code: ERR_CALL_FN_ONCE_REENTRANT_CALL`）を同期的に投げます。解決待ちの `Promise` を後から共有する呼び出しは対象外です。この制限は 3 つの関数に共通し、関数をまたいだ再入も対象です。詳しくはエラー処理の基本方針を見てください。

```ts
import { callFnOnce } from "call-fn-once";

const cacheMap: callFnOnce.CacheMap = new Map();

callFnOnce(cacheMap, "key", () => {
  return callFnOnce(cacheMap, "key", () => "inner"); // ReentrantCallError を投げる
});
```

シングルスレッドでも、外側の結果がまだキャッシュされていないため、内側の呼び出しは無限再帰になります。避けるにはキーを分けてください。

`InconsistentCacheError` と `ReentrantCallError` は `instanceof` と `code` のどちらでも判定できます。メッセージの文言による一致判定は推奨しません。

```ts errors.ts
import { callAbortableFnOnce, InconsistentCacheError, ReentrantCallError } from "call-fn-once";

const cacheMap: callAbortableFnOnce.CacheMap = new Map();

try {
  callAbortableFnOnce(cacheMap, "key", () => "ok");
} catch (error: unknown) {
  if (error instanceof InconsistentCacheError || error instanceof ReentrantCallError) {
    // キャッシュ不整合または同一キーでの同期的な再呼び出しです。
  }

  if ((error as { code?: unknown }).code === "ERR_CALL_FN_ONCE_INCONSISTENT_CACHE") {
    // キャッシュが不整合な状態です。直接操作を見直してください。
  }

  if ((error as { code?: unknown }).code === "ERR_CALL_FN_ONCE_REENTRANT_CALL") {
    // 同一キーでの同期的な再呼び出しです。キーを分けてください。
  }
}
```
